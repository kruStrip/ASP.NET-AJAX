МузЛото — этап 4: возвраты денег

Что меняется:
- Отмена ранее оплаченного заказа освобождает места и создаёт запрос Pending на возврат.
- В разделе /refunds администратор фиксирует фактический перевод: Completed.
- В отчёте отдельно валовые оплаты, возвраты и чистые поступления.
- Восстановление в течение часа аннулирует Pending-запрос; после Completed восстановление заблокировано.
- Нужна НОВАЯ миграция RefundWorkflow; запускается скриптом init-db.sh, данные не сбрасываются.

БЕЗОПАСНОЕ ПРИМЕНЕНИЕ НА КОМПЬЮТЕРЕ:
1. Остановите запущенный bash scripts/dev.sh через Ctrl+C.
2. Если БД содержит важные данные, сделайте резервную копию PostgreSQL.
3. Из ~/ASP.NET-AJAX распакуйте ZIP (из папки скачивания).
4. git add .github/workflows/muzloto.yml 4_курс/
   git commit -m "feat(muzloto): add manual refund workflow"
   git push origin main
5. Дождитесь зелёного GitHub Actions. Не запускать новую версию без миграции!
6. cd ~/ASP.NET-AJAX/4_курс/Разработка_веб_приложений_ASP.NET_AJAX/Итоговый_проект/проект
   bash scripts/init-db.sh
   bash scripts/dev.sh
7. Если миграция создана впервые:
   git add src/MuzLoto.Web/Data/Migrations/
   git commit -m "db(muzloto): add refund workflow migration"
   git push origin main

Итоговый архив содержит ТОЛЬКО изменённые файлы, НЕ включает .env, реальные пароли или базу данных.
CI будет генерировать миграцию из модели при необходимости и выполнять тесты на изолированной БД.
Ожидаемые ручные тесты описаны в docs/STAGE4.md.

Важно: заказы, отменённые ДО установки нового этапа, должны быть сверены вручную. Автоматического ретроспективного создания возвратов нет.

Статус: файлы прошли статические проверки, но не компилировались в этой среде (нет dotnet SDK). Требуется CI.
