# Соответствие правилам старой Google Sheets / Apps Script системы

Источник: предоставленный заказчиком Apps Script (около 1347 строк). Скрипт — справочный источник фактических рабочих правил; **при противоречии применяем согласованное единое ТЗ «МузЛото»**. Не переносить ошибки таблиц и не считать Google Sheets новой основой системы.

## Правила и эквиваленты

| Старый механизм | Новый эквивалент и состояние |
| --- | --- |
| `recalcPaidAmounts`: количество × цена | `Booking.TicketPriceSnapshot` и отдельный `Payment.Amount`. Платёж возникает **только после ручного подтверждения**; расчёт желаемой стоимости не означает поступления денег |
| `processGameConfirmations`: FALSE/TRUE перемещает строки между листами | `BookingStatus.Pending / Confirmed`. Подтверждение транзакционно проверяет места; обратная операция — отмена, затем восстановление в течение часа |
| `mergeDuplicatePurchaseRows`: одинаковые дата, игра, место, время, телефон и команда → сумма количества | Не сливать финансовые сущности автоматически. `ExternalSubmissionId` предотвращает повторное поступление одной заявки, а два самостоятельных заказа сохраняются раздельно. Группировка для отображения — отдельная задача |
| `fullRecalculate`: вместимость минус количество в покупках | Вычисляемый остаток = `GameSession.Capacity` − сумма `Quantity` у `Confirmed` заявок; отклонение при дефиците мест — HTTP 409 |
| `rewriteAvailabilityColumn`: список «Не выбрано», 1…N | Для API выдавать 1…min(остаток, `Integration:MaxTicketsPerBooking`), актуализируя динамически; интеграция формы FormDesigner требует проверки транспорта/полей |
| `syncPurchasesToAllTime`: копирование по ID | Основная БД хранит заявки и платежи постоянно; оперативные разделы фильтруют данные, отдельное физическое копирование не требуется |
| `restorePurchasesForKeys`: восстановление текущей выборки после снятия «Игра прошла» | Возврат сеанса в работу реализован. **Уже удалённые неоплаченные заявки не восстанавливаются**, согласно согласованному ТЗ |
| `removeFinishedGamePurchases`: скрыть покупки завершённых игр из текущего списка | `Bookings/Confirmed` исключает завершённые игры; оплаченные данные сохраняются в БД и финансовых отчётах |
| `cleanupDelayedFinishedGames`: через 24 часа очистить строки, не меняя ID | По согласованному ТЗ **оперативная видимость — 3 дня**, данные сеанса и финансовая история сохраняются. Периодическое физическое удаление не требуется для показа; сервис фоновой очистки/ретенции остаётся отдельной задачей |
| Ежеминутные `scheduledRecalculate` и `onEditInstallable` | Транзакции EF Core, SQL-агрегации, SignalR; для отложенных задач запланирован серверный `BackgroundService` |

## Наблюдаемые проблемы старого скрипта, которые нельзя переносить

1. Столбец «Оплатил» вычисляется как произведение количества билетов на цену независимо от доказательства фактической оплаты; при пересчёте архива это может вновь выставить сумму даже у неподтверждённой записи.
2. Объединение строк по телефону и команде может слить два самостоятельных платежа и уничтожить возможность поштучного аудита. В новой БД не объединяем `Booking`/`Payment` без ручной предметной процедуры.
3. Бизнес-ключ `дата+название+локация+время` изменяется при редактировании игры и зависит от форматов даты/времени. В новой системе используем стабильный `GameSession.Id` (UUID), историю/LegacyId сохраняем для миграции.
4. Отложенная очистка старого скрипта — 24 часа, но согласованное ТЗ требует три дня для видимости завершённого сеанса.

## Доработки этого пакета

- Восстановление отменённого бронирования в течение одного часа (`/bookings/cancelled`), с проверкой вместимости в Serializable-транзакции; повторный платёж не создаётся.
- Отмена завершения игры доступна только администратору; продажи остаются закрытыми, удалённые неоплаченные заявки не возвращаются.
- Скрытие завершённых игр из списка «Все игры» через три дня; финансовые записи остаются.
- Фактические поступления считаются по сохранённым `Payment`, а не по текущему статусу бронирования. При отмене места освобождаются, денежный возврат **не** осуществляется автоматически.
- Дополнены интеграционные PostgreSQL-тесты отмены, восстановления и отсутствия повторного платежа.
