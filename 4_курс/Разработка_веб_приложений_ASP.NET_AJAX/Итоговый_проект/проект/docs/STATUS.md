# Статус разработки «МузЛото»

## Этап 1 — базовый вертикальный сценарий

Код:
- Структура сущностей EF Core (Game, GameSession, Booking, Payment, History, ExternalSubmission, Images, staff assignments) и Identity;
- Интерфейсы: вход, панель, игры, создание/редактирование, ожидающие и подтверждённые покупки, завершение игр, общий отчёт;
- Canonical JSON интеграционный endpoint с отдельным секретом, защитой от дублей;
- Подтверждение оплаты в PostgreSQL Serializable-транзакции; мест меньше не становится при Pending;
- Завершение игры удаляет Pending, сохраняет подтверждённые покупки, источники внешних ID;
- Защищённый SignalR Hub (клиентская синхронизация запланирована позже);
- Unit-тесты бизнес-правил, Docker Compose для базы, сценарий инициализации миграций.

## Пока отсутствует / не проверено

- В этом окружении **нет .NET SDK, Docker и сетевого доступа к NuGet**. Исходный код не собирался, тесты не запускались. После переноса в GitHub необходим `dotnet build` и `dotnet test`, исправление возможных ошибок.
- Миграция **не сгенерирована**: её создаёт `scripts/init-db.sh` на ПК с SDK; сгенерированные файлы нужно закоммитить. До этого приложение запускать нельзя.
- Транспорт FormDesigner, точные имена полей, исходящая синхронизация и уведомления ещё не проверены. Endpoint принимает только нормализованный JSON от **доверенного адаптера**, но не обязательно исходный payload FormDesigner.
- Нет JWT API v1/v2, Swagger и полного CRUD, AJAX-операций и клиентского SignalR/reconnect, PWA.
- Не реализованы управление сотрудниками и назначениями из UI, изменение количества, восстановление отмены в 1 час, групповые отчёты, импорт истории, хранение фотографий, background jobs.
- Сводка и события в интерфейсе пока требуют обновления страницы, хотя сервер отправляет сигналы Hub.
- Нет end-to-end тестов с PostgreSQL и проверки конкуренции в реальной БД.
- Реальные ключи, персональные данные клиентов и база данных компании сюда не включены.
