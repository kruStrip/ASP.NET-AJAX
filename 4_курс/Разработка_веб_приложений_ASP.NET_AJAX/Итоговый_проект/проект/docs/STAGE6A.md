# Этап 6a — регистрация и собственные ресурсы пользователя

## Добавлено

- `/` — публичная главная: для гостя ссылки «Войти» и «Зарегистрироваться», для вошедшего — имя и кнопка «Выйти».
- `/account/register` — классическая Razor-форма с серверной валидацией. Новому пользователю всегда назначается роль **User**
  (права сотрудника выдаёт только администратор в `/staff`), затем автоматический вход и переход на главную.
- `Booking.OwnerUserId` (миграция `BookingOwner`, FK `SET NULL`, индекс) и страница `/bookings/mine` — только собственные заявки.
- Layout: имя пользователя, ссылки по роли, футер.
- `/account/denied` отвечает **403**, а не 200.
- `POST /api/auth/login` (старый `/api/auth/token` оставлен как алиас). JWT выдаётся любой роли и содержит id, e-mail и роли;
  доступ к данным по-прежнему проверяют эндпоинты (User на API сеансов получает 403).
- Dev-админ из `appsettings.Development.json`; `scripts/dev.sh` запускает приложение в Development (раньше Swagger локально не открывался).
- HTTP-тесты через `WebApplicationFactory` (`tests/MuzLoto.Tests/IdentityHttpTests.cs`).

## Обновление существующей базы

```bash
bash scripts/init-db.sh   # применит миграцию BookingOwner
bash scripts/dev.sh
```

## Проверка

- Автоматически: `MUZLOTO_PG_TEST=1` + отдельная тестовая БД → `dotnet test` (31 тест).
- Вручную: зарегистрироваться → попасть на главную с именем → открыть `/staff` → «Доступ запрещён» (403);
  `POST /api/auth/login` пользователем → токен; `GET /api/v1/sessions` с этим токеном → 403, без токена → 401.

## Ограничения

- Создавать заявки под своей учётной записью можно будет после этапа 6b (форма `/book`); до этого `/bookings/mine` пуст.
- API бронирований с фильтром по владельцу — этап 7.
