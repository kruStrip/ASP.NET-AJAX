# Контракт адаптера FormDesigner — первый этап

Существующая клиентская форма сохраняется. Режим отправки и параметры FormDesigner требуют проверки. **Не настраивайте эту конечную точку как прямой вебхук, пока не установлен формат, в котором сервис действительно передаёт данные.**

Защищённый входящий маршрут `POST /api/integrations/formdesigner/submissions` принимает JSON, предварительно преобразованный доверенным адаптером:

```json
{
  "externalSubmissionId": "fd-order-123",
  "gameSessionId": "00000000-0000-0000-0000-000000000000",
  "teamName": "Команда",
  "customerName": "Клиент",
  "phone": "+70000000000",
  "telegram": null,
  "quantity": 2
}
```

Аутентификация: `X-Integration-Key`, значение из `Integration__Secret` (не публикуется). Только HTTPS на внешнем сервере. Отсутствие секрета — 503; неверный секрет — 401; новая заявка — 201; повтор — 200 с `duplicate: true`; некорректные данные — 400; закрытая игра — 409.

## Известные зависимости перед запуском

- Установить исходный ID заявки, чтобы корректно обрабатывать повторы.
- Выяснить формат/механизм исходящей синхронизации списка игр и остатка мест.
- Выяснить, кем отправляются уведомления, чтобы не дублировать сообщения.
- Тестировать только на обезличенных заявках; номер телефона настоящего клиента не использовать в публичных тестах.
