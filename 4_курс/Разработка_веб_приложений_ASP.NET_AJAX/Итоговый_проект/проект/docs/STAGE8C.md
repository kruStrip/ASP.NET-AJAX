# Этап 8c — отчёты по играм и датам

Все отчёты раздела 6.4 ТЗ считает один сервис `Services/SalesReport.cs`; страница `/reports` и API используют его же.

| Отчёт | Где | Содержимое |
|---|---|---|
| Сводный | `/reports`, `GET /api/v1/reports/summary` | продано билетов, подтверждённая выручка, заказов, средний чек, билетов на заказ (за всё время) |
| По играм | `/reports`, `GET /api/v1/reports/by-game?from=&to=` | название, билетов, выручка, заказов (все даты игры вместе), итоговая строка |
| По датам | `/reports`, `GET /api/v1/reports/by-date?from=&to=` | дата сеанса, игра, билетов, выручка, заказов |
| История | `/bookings/history` (этап 8b) | все подтверждённые заказы и платежи за всё время |
| Оперативный | `/reports`, `GET /api/v1/reports/operational` | будущие игры: продано/вместимость, свободно, неоплаченные заявки и их билеты, открыты ли продажи |

- Период — по дате проведения игры (включительно).
- Выручка — подтверждённые оплаты минус **выполненные** возвраты (частичные и за отмену). Неоплаченные заявки продажами не считаются.
- Admin видит всё, Manager — только назначенные игры (API); страница `/reports` — только Admin.

## Проверка

59 тестов. Новый тест сверяет точные цифры: две даты одной игры складываются в строку «по играм», частичный возврат
уменьшает выручку, неоплаченная заявка не считается продажей, фильтр периода, оперативный отчёт (свободно / ждут оплаты),
страница с фильтром. Внешний вид проверен в браузере на демо-данных.
