# Этап 8a — карточка игры и сеансы

## Добавлено

- **Полная карточка.** Формы создания и редактирования (`_SessionFields`) содержат название и до пяти абзацев описания
  (общие для всех дат игры), дату, часовой пояс, место, ссылку на 2ГИС (только http/https), продолжительность,
  возрастное ограничение, цену и вместимость. Серверная валидация (Data Annotations + проверки ссылки и времени).
- **Несколько дат одной игры.** «Добавить дату» (`/events/create?gameId=`) создаёт новый сеанс с собственным ID;
  место, цена и вместимость подставляются из последней даты. В карточке — список других дат.
- **Карточка `/events/{id}`.** Описание, факты, продано/осталось, заявки и покупки, другие даты.
  Менеджер видит только назначенные игры (иначе 403), действия администратора ему не показываются.
- **Обложки.** Загрузка и замена (JPEG/PNG/WebP до 5 МБ; тип определяется по содержимому, а не по расширению).
  Файлы хранятся вне `wwwroot` и репозитория (`Storage:ImagesPath`, по умолчанию `App_Data/images`),
  выдаются сотрудникам по `/images/{id}?v={version}`. Замена увеличивает `Version` и удаляет старый файл.
  Обложка привязана к ID сеанса, поэтому смена даты её не отрывает (проверено тестом).
- **Архив.** Дату с покупками удалить нельзя — её можно перенести в архив (миграция `SessionArchive`, поле `ArchivedAt`):
  продажи закрываются, история сохраняется, игра пропадает из оперативных списков. Пока есть неподтверждённые
  заявки, архивирование запрещено. Дату без заявок можно удалить. В API v2 статус `archived`.
- **Поиск и фильтры** на `/events`: по названию и месту; статусы «Актуальные», «Продажа открыта/закрыта»,
  «Прошедшие», «Архив», «Все». Индекс по названию игры.

## Проверка

52 теста, в том числе 7 новых HTTP-тестов: полная карточка и вторая дата игры, серверная валидация,
**XSS**: `<script>alert('XSS')</script>` в описании выводится как текст; загрузка, замена и отказ для не-изображения,
обложка после смены даты, архив и правила удаления, поиск, доступ менеджера. Внешний вид проверен в браузере.
